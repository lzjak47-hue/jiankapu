# 05 · 后端：业务服务层

> 源码目录 [src/services/](../../apps/server/src/services/)。全异步函数、无 HTTP 概念，
> 只依赖 `db` / `lib` / `config` 与少量其它 service。依赖关系总表见 [10-依赖关系](./10-依赖关系与数据模型.md)。

## 1. auth.js — 后台认证与会话

职责：口令 / 验证码 / 会话 / 登录锁定全套。

| 导出 | 签名 | 说明 |
| --- | --- | --- |
| `createCaptcha` | `() → {id, svg, expiresInSeconds}` | 服务端自绘 SVG 验证码（内部 `renderCaptchaSvg`） |
| `verifyCaptcha` | `(id, input) → boolean` | **一次性消费**：无论对错都删除，防枚举；5 分钟过期 |
| `checkLock` | `(ip) → {locked, until?}` | 查询锁定状态 |
| `recordFail` | `(ip) → {failCount, locked, until}` | 记失败；阈值/时长从 settings 动态取 |
| `clearFail` | `(ip)` | 成功后清零 |
| `createSession` | `(adminId, {ip, userAgent}) → {token, ttlSeconds}` | 32B 随机令牌入 `sessions` 表 |
| `getSession` | `(token) → {token, admin} \| null` | 会话校验（配合过期清理） |
| `destroySession` | `(token) → boolean` | 单条销毁 |
| `purgeExpiredSessions` | `() → number` | 过期会话清理（定时任务调用） |
| `login` | `({...}) → {token, ttlSeconds, admin}` | 完整登录：检查锁定 → 验证码 → 口令 |
| `changePassword` | `(adminId, {oldPassword, newPassword}) → boolean` | 成功后**删除该管理员全部会话**（踢掉其它设备） |
| `listAdmins` | `()` | 管理员列表 |

安全细节：账号不存在时也执行一次假 scrypt 比对（防时间侧信道）；失败按 IP 计数锁定（默认 5 次 / 15 分钟）。

## 2. settings.js — 设置中心（读多写少）

| 导出 | 签名 | 说明 |
| --- | --- | --- |
| `reload` / `invalidate` | `()` | 启动全量载入内存缓存 / 保存后失效重载 |
| `getRaw` / `getNumber` / `getBool` | `(key, fb)` | 同步读取；数字/布尔转换；空串回落默认（防「未配置当 0」） |
| `toApi` / `toPublic` | `()` | 后台全量 / 前台脱敏视图 |
| `save` | `(payload) → 修改的 key 列表` | 白名单写入，**未知字段忽略** |
| `isChannelEnabled` / `isChannelConfigured` | `(channel)` | 「启用(rendered)」vs「密钥填全(configured)」 |
| `enabledChannels` / `availableChannels` / `channelMissingKeys` | `()` | 前台显示渠道 / 可收款渠道 / 缺失密钥清单 |
| `SETTING_KEYS` | 常量 | 全部合法设置键 |

- `SECRET_KEYS`（支付密钥、SMTP 授权码等）**永不回传**，响应只给 `xxxKeySet` 布尔；提交空值 = 不修改。
- 「已启用」和「能收款」是两件事：后台开了但密钥没填全 → 前台显示但标「暂不可用」置灰，下单 409。

## 3. payment.js — 支付编排（只管网关，不管订单状态）

| 导出 | 签名 | 说明 |
| --- | --- | --- |
| `CHANNELS` / `CHANNEL_CODES` | 常量 | 渠道元数据 / 编码列表 |
| `isValidChannel` / `labelOf` / `channelFromLabel` | | 渠道合法性 / 标记互转 |
| `createPayment` | `(order, channel) → {channel, label, qrCode, mode}` | 按渠道分发：wechat → nativeOrder、alipay → precreate、test → 本地构造 |
| `shouldQuery` | `(order)` | 该订单是否需要主动查单（待付款 + 真实渠道） |
| `queryPayment` | `(order) → {paid, closed, paidAmount, detail}` | 主动查单，**每单 5 秒节流**（Map 超 500 清过期项） |
| `parseWechatNotify` / `parseAlipayNotify` | `(body/params)` | 回调解密/验签 → 标准化结果 |
| `amountMatches` | `(orderAmount, paidAmount) → boolean` | 应付 vs 实付容差 <0.01，防改价支付 |

- 二维码有效期与本地关单时间对齐（微信 `time_expire` / 支付宝 `timeout_express`）。
- 金额单位换算（微信分→元）在解析层完成。

## 4. notify.js — 发货通知（尽力而为）

| 导出 | 签名 | 说明 |
| --- | --- | --- |
| `detectChannel` | `(contact) → "sms" \| "email" \| null` | 正则识别：手机号(含空格/短横线/+86)→短信，邮箱→邮件，其余 null |
| `sendMailNow` / `sendSmsNow` | `(…)` | 直接发送（异常上抛） |
| `notifyOrderPaid` | `(order, secrets) → {channel, sent, reason?}` | 发卡后调用，**绝不抛错**（失败仅日志，不影响已完成的支付） |
| `sendTest` | `(channel, target)` | 后台测试按钮——失败抛 `upstream(502)` 并透出真实原因 |

- 模板占位符 `{site}{orderNo}{product}{spec}{qty}{amount}{secrets}` 替换；短信用 `、` 拼接多条卡密。
- 邮件/短信开关在 settings 各自独立；未开启或识别不出直接跳过。

## 5. alerts.js — 后台提醒 feed（铃铛）

导出 `feed({since, orderLimit, stockLimit}) → 聚合事件对象`。

- `since` 游标存在浏览器 localStorage，**不建已读表**；多个管理员各看各的。
- 事件两类：新订单（含合计金额）在前、库存预警（仅**在架**商品，`soldOut = stock ≤ 0` 或低于阈值）在后。
- 首次打开以服务器当前时间为基准，不把历史订单当新订单刷屏。

## 6. category.js — 分类 CRUD

导出：`list({onlyEnabled})`、`find(id)`、`requireEnabled(id)`、`create(payload)`、`update(id, payload)`、`remove(id)`。

- `identifier` 创建后不可改；**分类下有商品时拒绝删除**；`list` 内联统计商品数。

## 7. product.js — 商品服务

| 导出 | 签名 | 说明 |
| --- | --- | --- |
| `toApi` | `(row, specStock)` | 行 → API 形状 |
| `list` | `(opts) → {rows, total}` | 后台列表：keyword/category/status + `PRODUCT_SORTS` 白名单排序 + 分页 |
| `listPublic` | `()` | 前台列表（在架商品 + `specStockMap` 批量取库存，避免 N+1） |
| `find` / `findRow` | `(id)` | 带/不带分类关联 |
| `requirePurchasable` | `(id, spec?)` | 下单前校验（存在、在架、规格有货） |
| `recomputeStock` / `recomputeAllStock` | `(id)` / `()` | 按未售卡密回写冗余 stock |
| `create` / `update` / `remove` / `toggleStatus` / `batch` | | CRUD + 上下架 + 批量（置为目标状态，单个失败不连累） |
| `lowStockProducts` | `()` | 库存预警列表 |

- 声明过的每个规格在 `specStock` 中**必有数字，无卡密就是 0**（不消失，前端才能显示「售罄」）。
- **规格改名/删除被拦截**：该规格下还有未售/锁定卡密时 409 并说明余量，防止孤儿卡密。

## 8. card.js — 卡密库存核心（状态机与并发安全）

卡密状态机：`未售 → 已锁定 → 已售`（订单关闭/超时由 release 回 `未售`）。

| 导出 | 签名 | 说明 |
| --- | --- | --- |
| `list` / `exportRows` | | 列表（`CARD_SORTS` 白名单排序）；导出同筛选数据（上限 5 万） |
| `stats` / `availableCount` / `specStock` / `specStockFor` | | 库存统计（按商品+规格摊开） |
| `importCards` | `(productId, spec, lines)` | 批量导入：**必须指定规格**并校验规格真实存在；事务内逐条判重（请求内 + 库内） |
| `batchRemove` / `remove` | | 批量删除**跳过已售**（留着与订单对账），回写库存计数 |
| `clearAvailable` | | 清空某规格全部未售/锁定卡密（配合规格改名） |
| `lockForOrder` | `(orderId, productId, spec, qty)` | **必须事务内调用**：`FOR UPDATE SKIP LOCKED` 从「商品+规格」池锁定，多请求并发不会抢同一条 |
| `commitForOrder` / `releaseForOrder` | | 发卡（已锁定→已售 + 写 `order_cards`，`ON CONFLICT` 幂等）/ 释放回未售 |
| `secretsForOrder` / `secretsForOrders` | | 取订单卡密内容 |
| `releaseOrphanLocks` | | 定时释放孤儿锁定 |
| `toApi` / `CARD_STATUS` | | 行映射 / 状态常量 |

## 9. order.js — 订单全链路（编排中枢）

订单状态机：`待付款 → 已发货`（正常）/ `已关闭`（取消/超时）/ `处理中 → 已退款`。

| 导出 | 签名 | 说明 |
| --- | --- | --- |
| `ORDER_STATUS` / `PAID_STATUSES` / `PAY_LABELS` | 常量 | |
| `toPublic` / `toAdmin` | `(row[, extras])` | API 形状转换 |
| `findRowByNo` / `findPublic` / `searchPublic` | `(no)` / `(keyword)` | 按单号 / 按单号或联系方式模糊查 |
| `list` / `stats` | | 后台列表（多条件 + 排序白名单 + 分页）/ 维度统计 |
| `create` | `({productId, spec, qty, contact, channel, ...})` | **下单**：先参数校验(400)再业务校验(409)；事务内 `lockForOrder` + 建订单；`createPayment` 放**事务外**（避免长期持有连接） |
| `markPaid` | `(order, {channel, paidAmount})` | **幂等发卡**：已发货直接返回原卡密；非 test 渠道禁止手动确认；超时则关单；事务内 commitForOrder + 用户建档；通知 fire-and-forget |
| `close` / `resend` / `refund` | `(no, …)` | 取消（释放卡密）/ 补发 / 退款（作废已售卡密不回库，销量 `GREATEST(sold-qty,0)`） |
| `sweepExpired` | `() → number` | 定时关超时单（释放锁定卡密） |

## 10. user.js — 客户档案（无账号体系）

导出：`list`、`stats`、`detail(uid)`、`findByUid`、`touchByContact`。

- 客户 = 下单时填的联系方式；空联系方式不建档；`last_ip` 记录最近下单来源（订单 `client_ip` 才是权威）。
- 累计消费只统计 `已发货/处理中` 订单；uid 形如 `U{100300+count}`；展示名取联系方式末尾 8 位。
- **无封禁功能**（封了换个联系方式照样能买），后台只做查询：买过什么、从哪些 IP 买。

## 11. stats.js — 后台数据概览

导出 `overview() → {stats, series, topProducts, recentOrders, system, orderStats}`。

- 全部实时聚合不缓存；`COUNT(*) FILTER` 单次查询多口径；同比 delta 计算 `pct()`；近 7 天逐日走势。
- 内部：`buildStats` / `buildSeries` / `buildTopProducts` / `buildRecentOrders` / `buildSystemInfo`。

## 12. log.js — 操作日志

导出：`write(entry)`、`list({keyword, result, page, perPage})`、`recent(limit)`。

- 所有后台写操作经路由层 `audit()` 调 `write()` 留痕（谁、何时、做了什么、结果）。
- 字段全截断防超长；`logs.time` 存 TEXT 本地时间串；`result` 精确匹配、其余 ILIKE 模糊。
