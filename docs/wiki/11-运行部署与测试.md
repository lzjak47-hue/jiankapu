# 11 · 运行、部署与测试

> 所有命令在**仓库根目录**执行（根 package.json 聚合全部 scripts）。

## 1. 环境要求

- Node.js ≥ 20（后端用 `--watch`、`import.meta.dirname` 等新特性）
- PostgreSQL ≥ 12（开发验证于 18.6）
- 包管理：pnpm（workspace），npm 也可用

## 2. 快速开始

```bash
# 1) 建库
psql -U postgres -c "CREATE DATABASE jiankapu_dev WITH ENCODING 'UTF8' TEMPLATE template0;"

# 2) 安装 + 构建前端（根目录一次搞定）
pnpm install
pnpm build            # 或 npm run setup

# 3) 启动（首次自动建表 + 灌演示数据）
npm start
```

| 入口 | 地址 | 账号 |
| --- | --- | --- |
| 前台商城 | http://localhost:2001/ | — |
| 管理后台 | http://localhost:2002/login | `admin / 123456` |

> ⚠️ 服务端只托管 `apps/web-react/dist` 产物：**前端必须先 build**，未构建时访问会看到「前端还没有构建」
> 提示页（而非 404）。前端改动后需重新 build，或开发时用 `npm run dev:web`（Vite HMR + `/api` 代理到 2002）。

## 3. 全部命令

| 命令 | 作用 |
| --- | --- |
| `npm start` | 启动双服务（site:2001 + admin:2002） |
| `npm run dev` | 后端 `node --watch` 自动重启 |
| `npm run start:site / start:admin` | 只启动前台 / 后台（`--only`） |
| `npm run dev:web` | 前端 Vite 开发服务器（5173，HMR） |
| `npm run build` | 前端 `tsc --noEmit && vite build` |
| `npm run seed` / `npm run reset` | 初始化演示数据 / `--force` 清空重建 |
| `npm test` | 后端测试（自动建独立测试库 `jiankapu_test`，不动开发数据） |
| `npm run test:web` | 前端组件测试 |
| `npm run test:all` | 两端全跑 |
| `apps/web-react` 内：`typecheck` | 仅 `tsc --noEmit` |
| `pnpm approve-builds` | pnpm 提示忽略 esbuild build script 时放行（不放行也能构建——二进制由 @esbuild/win32-x64 可选依赖提供） |

## 4. 环境变量（config.js 读取）

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `SITE_PORT` / `ADMIN_PORT` | 2001 / 2002 | 两端端口 |
| `HOST` | 127.0.0.1 | 对外服务改 `0.0.0.0` |
| `SITE_BASE_URL` / `ADMIN_BASE_URL` | `http://localhost:2001/2002` | 前端运行时注入与支付回调地址拼接 |
| `DATABASE_URL` | — | 完整连接串，设置后覆盖下面的 PG* 变量 |
| `PGHOST/PGPORT/PGUSER/PGPASSWORD/PGDATABASE` | 127.0.0.1 / 5432 / postgres / 开发默认 / `jiankapu_dev` | 分项连接信息 |
| `PGPOOL_MAX` | 10 | 连接池上限 |
| `WEB_DIST_DIR` | `apps/web-react/dist` | 前端产物目录（可指向独立部署位置） |
| `SESSION_SECRET` | 开发默认 | 生产**必须**覆盖 |
| `NODE_ENV` | development | `production` 开启静态资源缓存（3600s） |
| `DEBUG` | — | 打开 logger.debug 输出 |

## 6. 上线检查清单（README「必须处理的几件事」）

1. 关闭「测试支付」渠道（点一下就成功 = 免费领卡）。
2. `SITE_BASE_URL` 改为公网可达域名（否则微信/支付宝回调不到，只能靠 5s 节流的主动查单兜底）。
3. 数据库密码从 config 默认值移到环境变量/`.env`，并从仓库移除。
4. `SESSION_SECRET` 必须覆盖；建议会话令牌入库前按 secret 做 HMAC。
5. 修改默认管理员密码。
6. HTTPS：`buildCookie()` 支持 `secure`，生产置于反向代理后开启。
7. 后台端口（2002）限内网或加 IP 白名单。
8. `guestOrder` 设置项已存在但**未在下单链路强制校验**（当前设计允许游客下单）。
9. 多管理员/角色权限未实现，只有单一超管。
10. 二维码通过 25 项一致性测试但**未用实体扫码器验证**，上线前用手机实扫一次。
11. 真实支付未在线上跑过：填真实商户资料后先用小额真实交易验证全链路。
12. `apps/web/` 旧前端不再被引用，确认后可整目录删除。
13. `dist/` 未纳入版本控制，部署流程记得加 `npm run build`。

## 7. 排障速查

| 症状 | 原因/处理 |
| --- | --- |
| 端口被占用 | 换端口并改 BASE_URL 系列：`SITE_PORT=2011 ADMIN_PORT=2012 npm start` |
| 访问页面提示「前端还没有构建」 | `npm run build`（或 `WEB_DIST_DIR` 指向产物） |
| 无法连接 PostgreSQL | 检查 PG* 变量与库名；`initDatabase` 会给出可读错误 |
| pnpm 提示 Ignored build scripts: esbuild | 可执行 `pnpm approve-builds`，不放行也能构建 |
| 本地真实支付到账慢几秒 | 正常：回调到不了 localhost，靠轮询时顺带主动查单（5s 节流） |
| 后台测试通知失败 | 错误原样透出（502 + 真实原因），按提示排查配置 |
| 老库升级后某规格取不到卡密 | cards.spec 为空串（孤儿数据），重新按规格导入或 `npm run reset` |
