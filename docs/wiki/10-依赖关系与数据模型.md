## 2. 内部模块依赖关系

后端调用方向：`routes → services → (db, lib, config)`；服务间允许交叉调用。

```
routes/public.js ──► order · product · category · settings · payment · stats
routes/admin.js  ──► auth · settings · category · product · order · card · user · log · stats · notify · alerts
                         │
services/order.js ──► product · card · payment · notify · user · log · settings · lib(crypto/errors/validate/time) · db
services/product.js ─► category · lib · db       services/card.js ──► product · lib · db
services/auth.js ────► settings · lib(crypto/time/validate/errors) · db
services/payment.js ─► settings · lib(wechatpay/alipay/logger · time) · config
services/notify.js ──► settings · lib(mailer/sms/logger)
services/alerts.js ──► settings · db            services/stats.js ──► order · settings · db
lib/* ───────────────► 仅 node 内置 + config（qrcode 零依赖）
db.js ───────────────► pg + config + logger     index.js ──► 以上全部编排
```

前端（src/ 内部，所有相对 import 用别名 `@`）：

```
site/*  ──► shared/(types · api · hooks · format · components · Toast/Confirm · sort · styles) + react-router-dom
admin/* ──► shared/* 同上（不 import site/*）
shared/* ──► 仅依赖 react / react-dom；types.ts 无依赖（契约根）
```

关键约束：
- **`shared/types.ts` 是接口唯一事实来源**——改后端接口先改这里，`tsc` 指出所有同步点。
- **`shared/api.ts` 是唯一网络出口**——组件不直接 fetch。
- 前端**不产生循环依赖**：`shared` 被两个应用单向引用。

## 3. 数据模型（13 张表，来自 db.js SCHEMA）

> 时间列统一 TEXT 存 `"YYYY-MM-DD HH:mm:ss"` 本地时间串（lib/time.js），字典序即时间序。
> 金额统一 `NUMERIC(12,2)`，由连接池类型解析器转 JS Number。

### 系统表

| 表 | 关键列 | 用途 |
| --- | --- | --- |
| `settings` | `key PK`, `value` | 扁平 key/value 全站设置（如 `trade.minOrder`、`payment.wxEnable`） |
| `admins` | `username UNIQUE`, `nickname`, `role`, `password_hash`(scrypt), `last_login_at/ip` | 管理员（单一超管） |
| `sessions` | `token PK`, `admin_id FK→admins`, `expires_at`, `ip`, `user_agent` | 服务端会话（HttpOnly Cookie 只放 token） |
| `login_attempts` | `ip PK`, `fail_count`, `locked_until` | 登录失败计数与 IP 锁定 |
| `captchas` | `id PK`, `code`, `expires_at`, `used` | 一次性验证码 |
| `logs` | `time`, `actor`, `action`, `target`, `ip`, `result` | 后台操作审计 |

### 业务表

| 表 | 关键列 | 用途 |
| --- | --- | --- |
| `categories` | `id PK`(文本), `name`, `sort`, `status`, `remark` | 商品分类；`identifier` 不可改 |
| `announcements` | `text`, `status`, `sort` | 前台公告条 |
| `products` | `id PK`(文本), `category_id`, `price`/`old_price`, **`stock`(冗余计数)**, `sold`, `status`, `specs`(JSON 文本数组), `description/detail/notice/tutorial`(数组文本), `delivery`, `created_at/updated_at` | 商品；`specs` 声明规格，`specStock` 由 cards 实时计 |
| `cards` | `product_id`, **`spec`**, `secret UNIQUE`, `status`(未售/已锁定/已售), `imported_at`, `sold_at`, `order_id` | 卡密库存；索引 `(product_id,spec,status)` 是锁卡热路径 |
| `orders` | `order_no UNIQUE`, `product_id/name`, `spec`, `qty`, `unit_price`, `amount`, `contact`, `pay_method`(给人看), **`pay_channel`**(给程序: wechat/alipay/test), `status`, `pay_url`, `created_at`, `expires_at`, `paid_at`, `closed_at`, `client_ip` | 订单；`pay_channel` 为 v1.3 迁移加列（老单按中文标签回填） |
| `order_cards` | `order_id FK→orders ON DELETE CASCADE`, `card_id`, `secret`，复合主键 | 订单实发卡密快照（卡密被删仍可追溯） |
| `users` | `uid UNIQUE`, `name`(联系末 8 位), `contact`, `status`, `last_ip`, `reg_at`, `last_at` | 客户档案（无注册）；`last_ip` v1.2 迁移加列 |

### 迁移（MIGRATIONS，幂等）

| 版本 | 内容 |
| --- | --- |
| v1.1 | cards 加 `spec` 列 + 索引 `idx_cards_stock(product_id,spec,status)` |
| v1.2 | users 加 `last_ip` + 订单 `contact` 索引 |
| v1.3 | orders 加 `pay_channel`，老订单按 `pay_method` 中文标签回填 |

⚠️ 依赖新列的索引**只能写在迁移里**（建表语句在老库上会缺列报错）；存量卡密 upgrade 后 spec 为空串 =
对规格商品而言的孤儿数据，需重新按规格导入（演示数据 `npm run reset`）。

## 4. 两个状态机

- 订单：`待付款 → 已发货`（正常）/ `待付款 → 已关闭`（取消/超时）/ `处理中 → 已退款`。
- 卡密：`未售 → 已锁定 → 已售`；锁定可释放回 `未售`（取消/超时/孤儿清理）。

并发与一致性：
- 锁卡 `SELECT ... FOR UPDATE SKIP LOCKED WHERE product_id=? AND spec=? AND status='未售'`，仅事务内调用。
- 下单/发卡/补发/退款全走 `tx()`（AsyncLocalStorage 透传连接），失败回滚。
- `markPaid` 幂等：已发货订单重复回调直接返回原卡密，不重复发卡。
- 退款作废已售卡密**不回库**；销量 `GREATEST(sold-qty, 0)`；`products.stock` 全部由 `recomputeStock()` 从 cards 回写。
