## 1. index.js — 进程入口

无导出，`main()` 编排启动全流程：

1. `initDatabase()`：`SELECT 1` 连通自检 → 执行 `SCHEMA` 建表 → 执行 `MIGRATIONS` 幂等迁移，失败抛错退出。
2. `isInitialized()` 查 `admins` 计数，空库自动 `seed({ quiet: true })`。
3. `settingsService.reload()` 把设置载入内存缓存（业务层同步读取）。
4. 按 `--only site|admin`（缺省两个都启）循环 `startOne(role)`：
   `createServer(role)` → `http.createServer` → 监听 `config.servers[role]` 端口；
   捕获 `EADDRINUSE` / `EACCES` 给出换端口提示；任一失败则关闭已启动实例并退出。
5. 打印 `banner()`（两端入口、admin/123456、数据库与 Node 版本）。
6. 定时清理（`config.sweepIntervalSeconds` 默认 30s，`timer.unref()` 不阻塞退出）：
   `orderService.sweepExpired()` → `authService.purgeExpiredSessions()` → `cardService.releaseOrphanLocks()`。
7. `SIGINT` / `SIGTERM` 优雅退出：清定时器 → 关两个 server → `closePool()`。

命令行：`npm start` / `node apps/server/src/index.js --only site`（对应根脚本 `start:site`/`start:admin`）。

## 2. config.js — 全部可调参数

导出单一 `config` 对象，结构（节选）：

```js
config = {
  env,                       // NODE_ENV，默认 development
  servers: {
    site:  { name, host, port },   // SITE_PORT，默认 2001
    admin: { name, host, port },   // ADMIN_PORT，默认 2002
  },
  db: { host, port, user, password, database, poolMax, ... },  // DATABASE_URL 或 PG* 变量
  paths: { root, webDist },   // webDist = WEB_DIST_DIR || apps/web-react/dist
  session: { secret, ttlSeconds },   // SESSION_SECRET，生产必须覆盖
  scrypt: { N, r, p, maxmem },       // 64MB 上限
  order: { timeoutMinutes, sweepIntervalSeconds, ... },
  login: { maxAttempts, lockSeconds },
  staticCacheSeconds,         // production=3600，development=0
}
```

要点：
- 数据库连接优先取 `DATABASE_URL`，否则拼 `PGHOST/PGPORT/PGUSER/PGPASSWORD/PGDATABASE`（默认库 `jiankapu_dev`）。
- ⚠️ 数据库密码以明文默认值写在 config，仅用于本地开发；上线必须改环境变量并移除（见 [11-上线检查清单](./11-运行部署与测试.md)）。

## 3. db.js — PostgreSQL 数据层

依赖：`pg`、`node:async_hooks`、`node:module`、config、lib/logger。
是 README 所说「换数据库只需改两处」的其中一处（另一处是 SQL 方言）。

### 导出

| 符号 | 签名 | 说明 |
| --- | --- | --- |
| `pool` | `pg.Pool` | 类型解析器把 NUMERIC(1700)/BIGINT(20) 转 JS Number |
| `query` | `(sql, params=[])` | 原始查询，自动 `?`→`$n` |
| `get` | `(sql, ...params)` | 单行，无则 `undefined` |
| `all` | `(sql, ...params)` | 全部行 |
| `run` | `(sql, ...params)` | 写操作，返回 `{changes, lastInsertRowid}`；需 `RETURNING id` 才能取回自增 ID |
| `scalar` | `(sql, ...params)` | 单值（COUNT/SUM） |
| `tx` | `(fn)` | 事务（见下） |
| `initDatabase` | `()` | 建表 + 迁移 |
| `closePool` | `()` | 关池 |

`run` 返回的 `lastInsertRowid` 不是 PostgreSQL 原生概念，是本层为兼容 SQLite 风格代码而回填的「首个 `RETURNING id`」。

### 事务透传（AsyncLocalStorage）

```js
await tx(async () => {
  await run("INSERT INTO orders ... RETURNING id", ...);
  await cardService.lockForOrder(orderId, productId, qty);   // 内部 get/all/run 自动走同一事务连接
  // 抛错整体 ROLLBACK
});
```

要点：
- `toPg()` 用计数把 SQL 中的 `?` 依次替换为 `$1,$2…`（**SQL 中不能出现字面量 `?`**）。
- `SCHEMA`：13 张 `CREATE TABLE IF NOT EXISTS`。
- `MIGRATIONS`：独立幂等 DDL（如 `ALTER TABLE cards ADD COLUMN IF NOT EXISTS spec …` + 补索引），
  不能混进建表语句——老库启动时 `CREATE INDEX ... (spec)` 会因缺列直接报错。

## 4. defaults.js — 种子与兜底数据

导出常量（无依赖）：`DEFAULT_ADMIN`、`DEFAULT_SETTINGS`（扁平 key/value，全部设置项默认值）、
`DEFAULT_ANNOUNCEMENTS`、`DEFAULT_CATEGORIES`、`DEFAULT_PRODUCTS`（12 个演示商品，含 `seedStock`）、
`DEFAULT_USERS`、`DEMO_ORDER_NUMBERS`。

- 支付渠道 `wx/ali/test`：wx、ali 默认禁用，仅 `test` 开启（本地跑通全流程）。
- 通知模板含占位符 `{site}{orderNo}{product}{spec}{qty}{amount}{secrets}`。
- 个别演示商品 `seedStock=0`，故意呈现「售罄」态。

## 5. seed.js — 初始化/重建脚本

导出：`isInitialized()`、`seed({ force=false, quiet=false })`；也可 CLI 直跑（`node src/seed.js [--force]`，
根脚本 `npm run seed` / `npm run reset`）。

- `--force`：`truncateAll()` 后重建；能识别自身为入口（`process.argv[1]` 以 `seed.js` 结尾）才执行。
- 卡密批量插入每 200 行一批，`ON CONFLICT (secret) DO NOTHING` 幂等。
- 演示订单含 2 笔固定单号 + 近 7 天随机单；`insertOrder` 在事务内先查重防重复。
- 各规格按 `MIN_PER_SPEC=5` 补货；完成后按真实卡密 `recomputeStock()` 回写商品库存。
- `index.js` 启动时的自动 seed 与手动 `npm run reset` 复用同一实现。

## 6. 数据模型（13 张表）

`settings` `admins` `sessions` `login_attempts` `captchas` `categories` `announcements`
`products` `cards` `orders` `order_cards` `users` `logs` —— 字段级结构见 [10-数据模型](./10-依赖关系与数据模型.md)。

本层相关的几个要点：

- `products.stock` 是「所有规格未售卡密之和」的冗余计数，由 `recomputeStock()` 回写；真实库存以 `cards` 中 `status='未售'` 为准。
- `cards.spec` 是后加列（`MIGRATIONS` 补），存量卡密升级后 spec 为空串 = 孤儿数据，需按规格重新导入（演示数据 `npm run reset`）。
- `order_cards` 记录订单发出的具体卡密——卡密记录被删后订单仍可追溯。
- `settings` 是扁平 key/value，服务层按分区聚合并做类型转换，写入白名单校验。
